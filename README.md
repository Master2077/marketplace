# Проект MarketPlace

## Описание:

Учебный интернет-магазин с постепенным развитием в маркетплейс.

Каталог, избранное, заказы и профили пока используют демонстрационные данные.
Форма контактов сохраняет сообщения в базу; письма не отправляются.

Реализовано:

- `home` — главная страница: продавцы и популярные товары
- `catalog` — каталог продавцов с категориями и сортировкой
- `favorites` — избранное: 3 товара и 3 продавца
- `orders` — корзина с группировкой по продавцам и история из 4 заказов
- `user_profile` — профиль покупателя: Александр, 3 покупки, 3 избранных
- `seller` — страница автора: обложка, аватар, рейтинг, статистика и товары
- `contacts` — форма обратной связи: проверка полей, CSRF, сохранение в SQLite
  и сообщение об успешной отправке
- `ContactMessage`, `ContactForm` — модель и форма для сообщений с контактов
- `app.py` — отдельный учебный сервер на `http.server`: GET отдаёт страницы,
  POST печатает данные формы в консоль
- `static/css/common.css` и `static/css/<страница>.css` — общие стили и стили страниц

## Установка:

1. Клонируйте репозиторий (рабочая ветка — `develop`):

```
git clone -b develop https://github.com/Master2077/marketplace
cd marketplace
```

2. Установите Python 3.13 и создайте виртуальное окружение. Команды ниже — для PowerShell в папке проекта:

```
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

3. Создайте `.env` в корне проекта с новым случайным ключом (один раз):

```powershell
.venv\Scripts\python.exe -c "from pathlib import Path; from django.core.management.utils import get_random_secret_key; p = Path('.env'); p.open('x', encoding='utf-8').write('DJANGO_SECRET_KEY=' + get_random_secret_key() + '\n')"
```

Команда не выводит ключ и не перезаписывает существующий `.env`.
`.env.example` показывает имя переменной; `change-me` — заглушка, а не настоящий ключ.
Настройки загружают `.env` относительно папки проекта, независимо от диска и имени пользователя.
Если `DJANGO_SECRET_KEY` уже задана в окружении, она имеет приоритет над `.env`.
Не публикуйте `.env`: он, виртуальное окружение и база данных исключены из Git.

4. Примените миграции:

```
.venv\Scripts\python.exe manage.py check
.venv\Scripts\python.exe manage.py migrate
```

## Использование:

1. Запустите сервер:

```
.venv\Scripts\python.exe manage.py runserver
```

2. Откройте страницы:

- `http://127.0.0.1:8000/` — главная
- `/catalog/` — каталог
- `/favorites/` — избранное
- `/orders/` — заказы
- `/profile/` — профиль
- `/seller/` — страница автора
- `/contacts/` — контакты
- `/admin/` — админка (нужен `createsuperuser`)

3. Заполните форму на странице контактов: сообщение сохранится в базе,
   в браузере появится «Сообщение отправлено», а запись будет видна в админке.



## Зависимости и проверки

`requirements.txt` фиксирует версии пакетов для запуска через pip.
`pyproject.toml` и `poetry.lock` также включены в Git; для установки через Poetry
используйте `poetry install --no-root` (включая инструменты разработки).
При обновлении зависимостей согласованно обновляйте оба описания и lock-файл.

```powershell
.venv\Scripts\python.exe manage.py makemigrations --check --dry-run
```

Старые адреса `/*.html` перенаправляются на новые, сохраняя параметры запроса
и метод POST (код 308). Ссылки между страницами используют `{% url %}`.
Локальные CSS подключены через `{% static %}` и доступны под `/static/css/`.
Папка `static/js/` предназначена для JavaScript, `static/images/` — для изображений интерфейса.
Пока они пусты; `.gitkeep` сохраняет эти папки в Git. Загружаемые пользователями файлы относятся к `media/`.
На странице контактов собственные CSS по требованию курсовой остаются на jsDelivr
из ветки `main`: локальные изменения этих файлов там не видны до публикации и обновления кэша.
Bootstrap, иконки и изображения загружаются из интернета.

Основной сервер — Django (`manage.py runserver`). Старый `app.py` не используется
для Django-шаблонов. `DEBUG=True` подходит только для локальной разработки.
