# MarketPlace — учебный проект маркетплейса

Учебный веб-проект: интернет-магазин с единым тёмным интерфейсом, который постепенно
развивается в маркетплейс — площадку, где у каждого продавца или автора будет своя
страница, товары и покупатели.

Сейчас это **не коммерческий продукт**, а учебная работа: готовая вёрстка семи страниц,
Django-сервер с маршрутизацией и форма обратной связи. Реальной оплаты, доставки,
авторизации и хранения товаров в базе пока нет — эти части только предстоит сделать.

## Что уже работает

- **Семь страниц** с общим оформлением: главная, каталог, избранное, заказы,
  профиль покупателя, страница автора и контакты.
- **Единое боковое меню** на всех страницах: 240 px на компьютере, 70 px с иконками
  на телефоне. Активным подсвечивается только текущий раздел.
- **Django-проект**: семь приложений (по одному на страницу), маршрутизация,
  контроллеры и шаблоны.
- **Форма обратной связи** на странице «Контакты»: проверка полей, CSRF-защита,
  сохранение сообщения в базу и сообщение об успешной отправке.
- **Админка Django**, в которой видны сообщения с формы контактов.
- **Раздельные CSS-файлы**: общие стили и стили каждой страницы.
- **Учебный HTTP-сервер** `app.py` — отдельное курсовое задание: на GET отдаёт
  страницу «Контакты», на POST печатает данные формы в консоль.

Каждое приложение устроено одинаково: `views.py` с контроллером, `urls.py`
с маршрутом, `apps.py` с настройками и папка `templates/<приложение>/<страница>.html`.

Приложение профиля называется `user_profile`, а не `profile`, чтобы не совпадать
с именем стандартного модуля Python `profile`.

## Запуск

### 1. Виртуальное окружение

```powershell
cd C:\Users\maby\PycharmProjects\svag
.venv\Scripts\Activate.ps1
```

Если окружения нет:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install django python-dotenv
```

### 2. Секретный ключ

Настройки берут ключ из переменной окружения `DJANGO_SECRET_KEY` и подгружают
её через `load_dotenv` из внешнего файла. В `.env.example` лежит пример:

```
DJANGO_SECRET_KEY=change-me
```

Создайте локальный `.env` (он в `.gitignore`) или задайте переменную вручную:

```powershell
$env:DJANGO_SECRET_KEY = "ваш-ключ"
```

Путь к файлу с секретом прописан в `config/settings.py`. На другом компьютере его
нужно поправить или использовать переменную окружения. Настоящий ключ в репозиторий
не добавляется.

### 3. База данных и запуск

```powershell
.venv\Scripts\python.exe manage.py migrate
.venv\Scripts\python.exe manage.py runserver
```

Откройте <http://127.0.0.1:8000/>.

### 4. Админка

```powershell
.venv\Scripts\python.exe manage.py createsuperuser
```

Вход: <http://127.0.0.1:8000/admin/>. В разделе «Сообщения с формы» видны письма,
отправленные через страницу контактов.

## Как работает форма контактов

1. `GET /contacts.html` — контроллер `contacts.views.contacts` показывает пустую форму.
2. Пользователь заполняет «Имя», «Почту» и «Сообщение».
3. `POST /contacts.html` — `ContactForm` проверяет данные, затем сохраняет их
   в модель `ContactMessage`.
4. При успехе в шаблоне выводится «Сообщение отправлено», и форма очищается.
5. При ошибках запись не создаётся.

Форма защищена CSRF-токеном, а значения при выводе экранируются средствами Django.
Письма на почту пока не отправляются — сообщения только сохраняются в базе.

## Стили

- `css/common.css` — палитра, боковое меню, мобильная версия меню, ссылка «Контакты».
- `css/<страница>.css` — стили конкретной страницы.
- Django отдаёт стили по адресу `/css/...` (`STATIC_URL = "/css/"`).

Отдельно: страница «Контакты» подключает CSS с удалённого репозитория через jsDelivr
(`https://cdn.jsdelivr.net/gh/Master2077/marketplace@main/css/...`). Это требование
курсового задания. Из-за этого правки локальных стилей не видны на контактах, пока
они не отправлены в репозиторий и не истёк кэш CDN.

## Старый учебный сервер `app.py`

Это отдельное курсовое задание, не часть Django-приложения. Сервер на
`http.server` отдаёт страницы макета по адресам вида `/index.html`,
на неизвестный адрес возвращает «Контакты», а на POST печатает данные формы
в консоль и отправляет страницу-подтверждение.

```powershell
.venv\Scripts\python.exe app.py
```

Порт 8000 совпадает с `runserver`, поэтому одновременно их не запускают.
Сейчас `app.py` читает шаблон, в котором есть Django-теги, поэтому при запуске
в форме будут видны служебные вставки. Для работы над сайтом используется Django;
старый сервер оставлен как история курсовой.

## Чего пока нет

- Регистрации, входа и ролей покупателя/продавца.
- Настоящих товаров, заказов и избранного в базе — всё это демонстрационные данные.
- Серверной корзины и оформления заказа.
- Отзывов и рейтингов.
- Отправки писем с формы контактов.
- Автотестов.
- Настроек для продакшена: `DEBUG = True`, `ALLOWED_HOSTS` пустой,
  статика не собирается через `collectstatic`.

## Планы развития

1. Вынести общее меню в базовый шаблон `base.html`, перевести ссылки на `{% url %}`,
   а статику — на `{% static %}`.
2. Добавить модели: продавец, товар, категория, заказ, позиции заказа, избранное.
3. Сделать авторизацию и роли, привязать профиль к пользователю.
4. Перевести каталог, избранное и заказы на данные из базы.
5. Добавить отзывы, рейтинги и личный кабинет продавца.
6. Настроить отправку писем и защиту формы от спама.
7. Подготовить проект к деплою: тесты, `DEBUG = False`, `collectstatic`.

## Учебный контекст

Проект выполняется в рамках курса: сначала вёрстка и простой HTTP-сервер,
затем Django. Работа над макетом продолжается, поэтому интерфейс и структура
могут меняться. Все демонстрационные действия на JavaScript — имитация будущей
функциональности, а не работающий серверный магазин.
